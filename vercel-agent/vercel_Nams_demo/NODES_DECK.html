The problem

The model

Not the problem. Context windows are bigger than ever.

The gap

No durable place for what the agent learns to live.

And

No mechanism to bring it back at the right moment.

Why bigger windows don't fix it

A context window is a working set.
Not a memory.

The usual reflex — keep the last N messages, summarise the rest — fails in the least useful direction: the thing you needed is what got summarised away.

Conflating the two gives you an agent with perfect recall of the last twenty minutes and total amnesia about the last twenty sessions.

The bet

Memory isn't a pile of embeddings.
It's a context graph.

Similarity search answers

“What have I seen that reads like this?”

It doesn't know Priya is a person, that Acme is an organization, that she works at Acme, or that “concise, technical answers” is a standing instruction rather than a passing remark.

Every one of those is

a relationship.

A flat pile of text snippets has nowhere to put relationships. Vector stores give you recall. The graph gives you understanding.

Most memory providers pick one shape. Mem0 wraps the model — invisible, but the model can't reach for memory deliberately. Supermemory and Hindsight expose tools — visible, never guaranteed. NAMS ships both, over one client and one API key.

Three modes, one line

Where does memory sit in your control flow?

// app/api/chat/route.ts
const resolvedModel = mode === 'provider'
  ? createNamsProvider({ ...memoryConfig, baseProvider: openai, scope }).languageModel(MODEL_ID)
  : mode === 'middleware'
    ? createNams(memoryConfig).wrap(openai(MODEL_ID), scope)
    : openai(MODEL_ID);   // tools mode — deliberately unwrapped

In tools mode memory doesn't happen to the model. It happens because the model asks.

The honest trade

Middleware guarantees memory.
Tools mode makes it visible.

Transparent · provider & middleware

Retrieval and persistence happen unconditionally, in code. Nothing to render — so when retrieval picks the wrong six memories, you find out by reading the answer and squinting.

Model-driven · tools

Every memory operation is a tool call, so it's in the stream, so it renders. That's the panel you're about to see.

Tools mode's weakness — and the fix

Models skip bookkeeping tools.

Ours read a shouty MANDATORY — ALWAYS call query_memory first, saw the answer in visible history, and skipped it. The reply was correct — for that session.

prepareStep: enforceQueryMemory({ graceSteps: 2 })

Holds every step at toolChoice:'required' until memory has been consulted, then forces the call outright. Two steps of grace, not zero — an agent with database tools legitimately wants a schema lookup first.

What lands in the graph

Six typed nodes. Not six sentences.

Priya                          [Person]
Acme Analytics                 [Organization]
Bangalore                      [Location]
Python                         [ProgrammingLanguage]
graph data engineer            [Concept]
concise, technical responses   [preference]

Python was classified ProgrammingLanguage by the extraction model. That's a graph you can run Cypher against, join to your domain data, and audit — not an opaque service call.

What broke while building it

Four bugs worth your time.

  • The model decided it already knew. Skipped query_memory entirely — caught only because the panel didn't render.
  • found:false read as “unknown.” The agent apologised while holding a live Cypher connection. Memory is not the database.
  • Hardcoded MCP tool names. Fine locally, broken against hosted Aura. Generate capability prompts from observed capability, never from config.
  • Graph extraction silently never ran. One .optional() in a Zod schema vs. OpenAI strict mode — every call failed and fell back to a flat entity.
The one that surprised us

Memory can eat its own tail.

Ask “what do you remember about me?”. The agent answers. That answer gets stored. Extraction turns it into entities:

long-term memories  [Concept]  — "Retrieved long-term memories indicate…"
past interactions   [Event]    — "The text lists past interactions as a category…"

Ask again, and those meta-entities outrank the real facts — so the agent tells you about remembering instead of about you. It compounds every time you ask — and it's the single most-asked question in any memory demo.

The finding that surprised us most

Retrieval quality is a property
of an index you can't see.

“which text editor do I use?”External workspaceManaged workspace
Result(none)Neovim, TechCorp, Alex…
RetrievalCase-sensitive substring on namesVector similarity

Same code. Same API calls. The service silently degrades to substring matching when the workspace has no vector index — and nothing in the API surface tells you which one you're on. The trade: colocation with your domain data, or working semantic recall.
